# 기상청 초단기실황 수신

## 설정·경로

- 서버 환경변수 KMA_WEATHER_SERVICE_KEY: 공공데이터포털 단기예보 조회서비스 인증키. 디코딩/인코딩 형태를 처리하며 프론트에 공개하지 않는다.
- GET /api/v1/external/weather?latitude=37.5665&longitude=126.9780
- 실제 제공기관 URL은 코드에 고정한다. 요청자가 URL이나 키를 전달하는 기능은 제공하지 않는다.
- 새 DB 쓰기·마이그레이션 없이 관측자료를 조회한다.

## 데이터·장애 정책

기상청 getUltraSrtNcst JSON 응답에서 T1H·REH·WSD·VEC를 읽는다. 위경도를 공식 5km Lambert 격자로 변환하고 응답 시각·격자를 확인한다. 누락·결측·범위 밖은 null, 실제 0은 0이다. 미관측 영역은 값이 없을 수 있다.

발표 지연을 피하기 위해 현재 KST의 지난 정시 자료부터 요청한다. NO_DATA인 경우에만 한 시간 더 이전 자료를 1회 요청한다. 따라서 가장 최신 발표 시각을 보장하는 구현은 아니다. 관측시각을 항상 표시한다. 요청별 timeout은 3.5초다.

서버 캐시는 격자별 5분, 장애 시 마지막 정상값 최대 추가 30분이며 STALE 상태를 함께 반환한다. servedAt은 서버 응답 시각, observedAt은 기상 관측시각이다. 캐시 반환시각을 새 관측시각으로 사용하지 않는다.

400: 위치 누락·영역 밖 / 503: 인증키 미설정 / 502: 제공기관 오류·미관측·응답 이상. 기상청 원문 오류·요청 URL에는 인증키가 포함될 수 있어 응답에 전달하지 않는다.

관측값은 인근 격자 대표값이다. 풍선 탑재 센서 실측이나 현장 순간풍속으로 해석하지 않는다.

## 검증 상태

자동 시험은 고정 표본으로 파싱·좌표·시간·결측·실패 처리를 확인한다. 실제 인증키를 사용한 제공기관 응답과 브라우저 운영 검증은 별도다. 아직 실제 응답 검증을 수행하지 않았다.

### 로컬 실제 응답 확인

인증키는 서버 폴더의 Git 제외 .env에 KMA_WEATHER_SERVICE_KEY로 설정한다. npm ci 이후 아래 명령으로 직접 기상청을 조회한다. 예시는 서울 좌표이며 실제 실증 위치로 바꿔 확인한다. 명령은 DB나 장치를 변경하지 않으며 출력에 인증키·요청 URL을 포함하지 않는다.

```powershell
npm run check:weather -- 37.5665 126.9780
```

2026-11-14 작업 환경에서 제공된 인증키를 사용해 호출을 시도했으나 Node 요청은 timeout, 별도 HTTP 요청은 HTTP 503으로 끝났다. 유효 관측 응답을 받지 못했으므로 키 승인·정상 수신을 확인한 것으로 판정하지 않는다. 사용자 노트북 또는 검증 서버에서 재확인이 필요하다. 키는 코드·문서·Git에 저장하지 않았다.

## 노트북 대시보드 연결

사용자 노트북에서 check:weather 실제 수신 성공을 확인했다(2026-11-14 13:00 KST, 서울 격자 60/127). 이는 사용자 제공 실행 결과이며 브라우저 통합 시험과는 구분한다.

DB 설정 없이 날씨만 실행하려면 서버 루트에서 npm run start:weather 를 사용한다. 127.0.0.1:18891에 바인딩하며 GET /health 및 /api/v1/external/weather만 제공한다. 프론트는 .env.local의 VITE_WEATHER_API_BASE_URL=http://127.0.0.1:18891 로 지정한다. 다른 관제 API 기본값은 유지한다. 두 서버를 모두 실행한 상태에서 브라우저로 확인한다.

운영은 기존 Core 서버의 동일 weatherRoutes를 사용한다. 날씨 전용 로컬 서버를 인터넷에 공개하는 설정은 추가하지 않는다.

## 강수·예보·특보 확장 (2026-11-14)

- 실황 `/api/v1/external/weather`에 `precipitation1hMm`(1시간 강수량, mm)와 `precipitationType`(PTY)을 추가한다. 미수신·기상청 결측 코드는 null이며 실제 0과 구분한다.
- 예보 `/api/v1/external/weather/forecast?latitude=...&longitude=...`는 동일 격자의 초단기예보를 사용한다. `issuedAt`은 발표시각, `periods[].validAt`은 예보 대상시각이다. 현재보다 미래이며 6시간 이내인 자료만 반환한다. 수치·범주형 강수 예보를 그대로 구분한다.
- 발표 직후 미제공 구간을 피하도록 이전 시간 30분 발표를 요청하고 NO_DATA일 때만 한 시간 전으로 재시도한다. 키·권한 오류를 반복 호출하지 않는다.
- 특보 `/api/v1/external/weather/warnings`는 `WthrWrnInfoService/getPwnStatus` 전국 현황 원문이다. 좌표별 해당 여부를 추론하지 않는다. `issuedAt`·`effectiveAt`·`checkedAt`을 구분한다. 7일 범위를 벗어난 발표·빈 본문·권한 거부는 자료 없음/오류이며 ‘특보 없음’이 아니다.
- 실황·예보·특보는 각각 별도 경로와 캐시를 사용한다. 예보 장애 시 실황은 유지되며 특보는 장애 시 과거 캐시 대체를 하지 않는다. 브라우저에 남은 마지막 특보는 지연 안내와 함께 표시한다.
- 특보 서비스는 공공데이터포털의 **기상청_기상특보 조회서비스** 활용신청이 별도로 필요하다. 같은 일반 인증키로 시도하며 다른 키가 필요하면 서버 `.env`에 `KMA_WARNING_SERVICE_KEY`를 설정한다. 키는 브라우저·Git에 넣지 않는다.

### 실제 응답 확인

서버 루트에서 아래 명령을 실행하면 실황·예보·전국 특보를 각각 확인한다. 각 경로는 GET으로 외부 자료만 읽으며 DB·장치 제어는 하지 않는다. 하나라도 실패하면 종료코드는 1이고 나머지 서비스 결과도 함께 출력한다.

```powershell
npm.cmd run check:weather:outlook -- 36.37369 127.33471
```

개발 환경의 실제 호출 시도에서는 세 서비스 모두 PROVIDER_UNAVAILABLE로 실제 응답을 받지 못했다. 사용자 노트북에서는 기존 실황 수신만 확인된 상태이며 **이번 확장의 실제 예보·특보 수신은 미검증**이다. 자동시험의 표본 응답을 실제 관측 결과로 취급하지 않는다.

## 예보 기준정보·특보 접근 거부 진단

사용자 노트북의 초단기실황은 성공했으나 초단기예보는 INVALID_RESPONSE(발표시각·격자 불일치), 특보는 상위 HTTP 403을 반환했다. 예보 원문이 아직 확보되지 않아 정확한 불일치 원인은 확정하지 않는다.

예보 날짜·시간은 숫자/문자열을 모두 정규화하고 앞자리 0을 보존한다. 요청 발표시각·격자 검증은 유지하며 불일치 시 requested/returned 기준정보만 허용 목록으로 출력한다. 원문 payload·인증키·요청 URL은 출력하지 않는다. 수정 후 사용자 노트북의 check:weather:outlook 실행으로 실제 수신을 재검증해야 한다.

특보 401/403은 KMA_WARNING_ACCESS_DENIED, 예보 401/403은 KMA_FORECAST_ACCESS_DENIED로 구분한다. 특보는 공공데이터포털 기상특보 조회서비스(15000415)의 특보현황조회 기능 이용 권한을 확인한다. 403만으로 심의 중/키 오류/정책 차단 중 정확한 사유를 확정하지 않는다.
