# 기상청 초단기실황 수신

## 설정·경로

- 서버 환경변수 KMA_WEATHER_SERVICE_KEY: 공공데이터포털 단기예보 조회서비스 인증키. 디코딩/인코딩 형태를 처리하며 프론트에 공개하지 않는다.
- GET /api/v1/external/weather?latitude=37.5665&longitude=126.9780
- 실제 제공기관 URL은 코드에 고정한다. 요청자가 URL이나 키를 전달하는 기능은 제공하지 않는다.
- 새 DB 쓰기·마이그레이션 없이 관측자료를 조회한다.

## 데이터·장애 정책

기상청 getUltraSrtNcst JSON 응답에서 T1H·REH·WSD·VEC를 읽는다. 위경도를 공식 5km Lambert 격자로 변환하고 응답 시각·격자를 확인한다. 누락·결측·범위 밖은 null, 실제 0은 0이다. 미관측 영역은 값이 없을 수 있다.

발표 지연을 피하기 위해 현재 KST의 지난 정시 자료부터 요청한다. NO_DATA인 경우에만 한 시간 더 이전 자료를 1회 요청한다. 따라서 가장 최신 발표 시각을 보장하는 구현은 아니다. 관측시각을 항상 표시한다. 요청별 timeout은 3.5초다.

서버 캐시는 격자별 5분, 장애 시 마지막 정상값 최대 추가 30분이며 STALE 상태를 함께 반환한다. servedAt은 서버 응답 시각, observedAt은 기상 관측시각이다. 캐시 반환시각을 새 관측시각으로 사용하지 않는다.

400: 위치 누락·영역 밖 / 503: 인증키 미설정 / 502: 제공기관 오류·미관측·응답 이상. 기상청 원문 오류·요청 URL에는 인증키가 포함될 수 있어 응답에 전달하지 않는다.

관측값은 인근 격자 대표값이다. 풍선 탑재 센서 실측이나 현장 순간풍속으로 해석하지 않는다.

## 검증 상태

자동 시험은 고정 표본으로 파싱·좌표·시간·결측·실패 처리를 확인한다. 실제 인증키를 사용한 제공기관 응답과 브라우저 운영 검증은 별도다. 아직 실제 응답 검증을 수행하지 않았다.

### 로컬 실제 응답 확인

인증키는 서버 폴더의 Git 제외 .env에 KMA_WEATHER_SERVICE_KEY로 설정한다. npm ci 이후 아래 명령으로 직접 기상청을 조회한다. 예시는 서울 좌표이며 실제 실증 위치로 바꿔 확인한다. 명령은 DB나 장치를 변경하지 않으며 출력에 인증키·요청 URL을 포함하지 않는다.

```powershell
npm run check:weather -- 37.5665 126.9780
```

2026-11-14 작업 환경에서 제공된 인증키를 사용해 호출을 시도했으나 Node 요청은 timeout, 별도 HTTP 요청은 HTTP 503으로 끝났다. 유효 관측 응답을 받지 못했으므로 키 승인·정상 수신을 확인한 것으로 판정하지 않는다. 사용자 노트북 또는 검증 서버에서 재확인이 필요하다. 키는 코드·문서·Git에 저장하지 않았다.

## 노트북 대시보드 연결

사용자 노트북에서 check:weather 실제 수신 성공을 확인했다(2026-11-14 13:00 KST, 서울 격자 60/127). 이는 사용자 제공 실행 결과이며 브라우저 통합 시험과는 구분한다.

DB 설정 없이 날씨만 실행하려면 서버 루트에서 npm run start:weather 를 사용한다. 127.0.0.1:18891에 바인딩하며 GET /health 및 /api/v1/external/weather만 제공한다. 프론트는 .env.local의 VITE_WEATHER_API_BASE_URL=http://127.0.0.1:18891 로 지정한다. 다른 관제 API 기본값은 유지한다. 두 서버를 모두 실행한 상태에서 브라우저로 확인한다.

운영은 기존 Core 서버의 동일 weatherRoutes를 사용한다. 날씨 전용 로컬 서버를 인터넷에 공개하는 설정은 추가하지 않는다.
